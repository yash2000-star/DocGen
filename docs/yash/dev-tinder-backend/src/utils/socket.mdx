# Socket Utilities

This file contains utility functions for initializing and managing real-time communication using Socket.IO. It handles user connections, chat room management, and message broadcasting.

## Overview

The `socket.js` utility is responsible for setting up and managing WebSocket connections for real-time features, primarily for chat functionality. It integrates with Socket.IO to handle connections, disconnections, joining chat rooms, and broadcasting messages between users. This utility is imported and used in `src/app.js` to establish the real-time communication layer for the application.

## Socket Events

The following events are handled by the Socket.IO server:

### `connection`

This event is triggered whenever a new client connects to the Socket.IO server. It logs the newly connected socket's ID to the console.

### `joinChat`

When a user wants to join a chat, this event is emitted. It generates a unique room name based on the sorted user IDs of the participants and joins the socket to that room.

<ParamField name="userId" type="string" required>
  The ID of the user initiating the join.
</ParamField>
<ParamField name="targetUserId" type="string" required>
  The ID of the user they wish to chat with.
</ParamField>

```javascript
socket.on("joinChat", ({ userId, targetUserId }) => {
  const ids = [userId, targetUserId].sort();
  const roomName = crypto
    .createHash("sha256")
    .update(ids.join(""))
    .digest("hex");
  socket.join(roomName);
  console.log(`User ${userId} joined room: ${roomName}`);
});
```

<Note>
The room name is generated using SHA256 hashing on the sorted participant IDs. This ensures that regardless of which participant initiates the `joinChat` event, they will always join the same room for a given chat pair.
</Note>

### `sendMessage`

This event handles the broadcasting of chat messages. It first checks if a chat document exists between the sender and receiver. If not, it creates a new one. The message is then saved to the database, and finally, it's broadcast to all clients in the corresponding chat room, excluding the sender.

<ParamField name="senderId" type="string" required>
  The ID of the user sending the message.
</ParamField>
<ParamField name="targetUserId" type="string" required>
  The ID of the user receiving the message.
</ParamField>
<ParamField name="text" type="string" required>
  The content of the message.
</ParamField>

```javascript
socket.on("sendMessage", async ({ senderId, targetUserId, text }) => {
  try {
    if (!senderId || !targetUserId || !text) {
      return console.error("sendMessage event received with missing data.");
    }

    let chat = await Chat.findOne({
      participants: { $all: [senderId, targetUserId] },
    });

    if (!chat) {
      chat = new Chat({
        participants: [senderId, targetUserId],
        messages: [],
      });
    }

    chat.messages.push({ senderId: senderId, text: text });
    await chat.save();

    const ids = [senderId, targetUserId].sort();
    const roomName = crypto
      .createHash("sha256")
      .update(ids.join(""))
      .digest("hex");

    socket.broadcast
      .to(roomName)
      .emit("messageReceived", { senderId, text });
  } catch (err) {
    console.error("Error in sendMessage:", err);
  }
});
```

<Warning>
Ensure `senderId`, `targetUserId`, and `text` are always provided. Missing data can lead to errors in chat history creation and message delivery.
</Warning>

### `disconnect`

This event is triggered when a client disconnects from the Socket.IO server. It logs the disconnected socket's ID.

## Usage Example

This utility is typically imported and used in your main application file (`src/app.js`) to set up the real-time communication layer.

```javascript
// In src/app.js
const http = require('http');
const initializeSocket = require('./utils/socket');

const server = http.createServer(app); // Assuming 'app' is your Express app
const io = initializeSocket(server);

// ... rest of your server setup
```

## Dependencies

This utility depends on the following modules:

*   `socket.io`: For real-time bidirectional event-based communication.
*   `../models/chat`: The Mongoose model for storing chat data.
*   `crypto`: Node.js built-in module for generating secure room names.

## Environment Variables

The `CORS` origin is determined by the `NODE_ENV` environment variable:

*   **`production`**: Uses `https://www.your-live-app-domain.com`.
*   **Any other value (e.g., `development`)**: Uses `http://localhost:5173`.

<Info>
It is crucial to set the `NODE_ENV` environment variable correctly for your deployment.
</Info>
