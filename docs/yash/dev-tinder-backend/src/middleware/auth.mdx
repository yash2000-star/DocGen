# Authentication Middleware

This middleware handles user authentication by verifying JWT tokens provided in request cookies, ensuring that only authenticated users can access protected resources.

## Overview

The `auth.js` middleware plays a crucial role in securing API endpoints by verifying the authenticity of incoming requests. It extracts a JWT from the request's cookies, validates it against a secret key, and then retrieves the corresponding user from the database. If successful, it attaches the user object to the request for subsequent middleware or route handlers to use.

## Parameters / Configuration

This middleware does not accept direct configuration parameters. It relies on environment variables for its operation.

<Warning>
  The JWT secret is a critical security parameter. Ensure `process.env.JWT_SECRET` is set securely and is not exposed.
</Warning>
<Info>
  This middleware relies on the presence of a JWT token in the request's cookies. For more information on cookie handling, refer to the documentation for your cookie parsing middleware.
</Info>

## User Authentication Middleware (`userAuth`)

Verifies a JWT token from request cookies to authenticate a user.

This middleware is used to protect routes that require user authentication. It extracts a JWT from the `token` cookie, verifies its validity using `process.env.JWT_SECRET`, and then attempts to find the associated user in the database using the `User` model. If successful, the user object is attached to the `req.user` property, and the request proceeds to the next middleware or route handler. If any step fails (e.g., missing token, invalid token, user not found), an appropriate error response is sent.

### Parameters

<ParamField name="req" type="object" required>
  The Express request object.
  <Expandable title="req properties">
    <ParamField name="req.cookies" type="object">
      An object containing cookies sent with the request. Expected to contain a `token` property.
    </ParamField>
  </Expandable>
</ParamField>
<ParamField name="res" type="object" required>
  The Express response object.
</ParamField>
<ParamField name="next" type="function" required>
  The next middleware function in the stack.
</ParamField>

### Security and Data Risks

<Warning>
  Exposure of the `JWT_SECRET` can lead to the forging of authentication tokens, compromising user accounts and data.
</Warning>
<Warning>
  If the token is invalid or expired, sensitive operations will be blocked, but user data remains protected.
</Warning>

### Usage Example

This middleware is typically used in route definitions to protect specific endpoints.

```javascript
// Example usage in src/routes/user.js
const express = require('express');
const { userAuth } = require('../middleware/auth');
const User = require('../models/user');

const router = express.Router();

// Protected route: Requires authentication
router.get('/profile', userAuth, async (req, res) => {
  // Access user details from req.user, which was populated by userAuth
  res.json({ message: 'Welcome to your profile!', user: req.user });
});

module.exports = router;
```

### Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="Error: Please Login!">
    This error occurs when the `token` cookie is not found in the request. Ensure that a JWT token is being set in the cookies after a successful login and that your cookie-parsing middleware is correctly configured.
  </Accordion>
  <Accordion title="Error: ERROR: jwt malformed">
    This indicates that the JWT token provided is not in the correct format. This could be due to corruption or an incorrect token being sent.
  </Accordion>
  <Accordion title="Error: ERROR: User not found">
    This means the user ID extracted from the JWT does not correspond to any existing user in the database. This could happen if a user account was deleted after the token was issued.
  </Accordion>
  <Accordion title="Error: invalid signature">
    This error signifies that the JWT signature is invalid, meaning the token has been tampered with or was signed with a different secret key.
  </Accordion>
</AccordionGroup>
