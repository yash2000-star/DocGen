# `src/models/user.js` - User Model Definition

This file defines the Mongoose schema for user objects, including data fields like `firstName`, `emailId`, and `password`, along with custom methods for JWT generation and password validation. It serves as the primary data model for user-related operations throughout the application.

## Overview

The `User` model encapsulates the structure and behavior of user data within the system. It integrates with MongoDB via Mongoose and provides methods crucial for authentication and user profile management.

## Parameters / Configuration

<ParamField name="firstName" type="string" required>

## Methods

The `User` schema includes several instance methods accessible directly on user objects.

### `getJWT()`

Generates and returns a JSON Web Token (<Tooltip tip="JSON Web Token — a signed authentication credential">JWT</Tooltip>) for the authenticated user, valid for 1 day.

<Warning>
  The JWT secret (`"DEV@Tinder$790"`) is currently hardcoded in the source. This is a critical security risk as it exposes sensitive information and makes token revocation difficult. For production environments, this secret **must** be moved to an environment variable and kept secure.
</Warning>

<ResponseField name="token" type="string">
  A signed JWT token string, typically used in the `Authorization` header for subsequent authenticated requests.
</ResponseField>

```javascript
userSchema.methods.getJWT = async function () {
    const user = this;
    const token = await jwt.sign({ _id: user._id }, "DEV@Tinder$790", {
                expiresIn: "1d"
            });
    return token;
}
```

### `validatePassword(passwordInputByUser)`

Compares a plain-text password provided by the user against the hashed password stored in the database for this user. Uses `bcrypt` for secure comparison.

<ParamField name="passwordInputByUser" type="string" required>
  The plain-text password string entered by the user during login or verification.
</ParamField>

<ResponseField name="isPasswordValid" type="boolean">
  `true` if the `passwordInputByUser` matches the stored hashed password, `false` otherwise.
</ResponseField>

```javascript
userSchema.methods.validatePassword = async function (passwordInputByUser) {
    const user = this;
    const passwordHash = user.password;
    const isPasswordVaild = await bcrypt.compare(passwordInputByUser, passwordHash);
    return isPasswordVaild;
}
```

## Usage Example

This example demonstrates how to create a new user, generate a JWT, and validate a password using the `User` model. This model is typically imported and used by controllers in `src/controllers` (e.g., `src/routes/auth.js`) for user authentication and management.

<CodeGroup>
```javascript JavaScript
const User = require('../models/user');
const bcrypt = require('bcrypt'); // Needed for hashing before saving

async function registerAndLoginUser() {
  try {
    // 1. Create a new user (password should be hashed before saving)
    const hashedPassword = await bcrypt.hash("MyStrongPass123!", 10);
    const newUser = await User.create({
      firstName: "Jane",
      lastName: "Doe",
      emailId: "jane.doe@example.com",
      password: hashedPassword,
      age: 28,
      gender: "Female"
    });
    console.log("User registered:", newUser);

    // 2. Generate a JWT for the new user
    const token = await newUser.getJWT();
    console.log("Generated JWT:", token);

    // 3. Validate a password
    const isPasswordCorrect = await newUser.validatePassword("MyStrongPass123!");
    console.log("Password validation successful:", isPasswordCorrect); // Should be true

    const isIncorrectPasswordCorrect = await newUser.validatePassword("WrongPass123!");
    console.log("Incorrect password validation successful:", isIncorrectPasswordCorrect); // Should be false

  } catch (error) {
    console.error("Error during user operations:", error.message);
  }
}

registerAndLoginUser();
```
</CodeGroup>

## Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="Invalid Email Address">
    <Info>
      This error occurs when the `emailId` provided does not pass the `validator.isEmail()` check during schema validation.
    </Info>
    <Note>
      Ensure the email format is correct (e.g., `user@example.com`). Spaces or missing domains will cause this error.
    </Note>
  </Accordion>
  <Accordion title="Not a Strong Password">
    <Info>
      The `password` field has a custom validator that checks for strong password criteria using `validator.isStrongPassword()`.
    </Info>
    <Tip>
      Refer to the `validator.isStrongPassword` documentation for specific requirements, which typically include minimum length, and a mix of uppercase, lowercase, numbers, and symbols.
    </Tip>
  </Accordion>
  <Accordion title="Duplicate Email Address (E11000 duplicate key error)">
    <Info>
      The `emailId` field has a `unique: true` constraint. MongoDB will throw an `E11000 duplicate key` error if you attempt to create a user with an `emailId` that already exists in the database.
    </Info>
    <Check>
      Before creating a new user, you might want to query the database to check for existing email IDs to provide a more user-friendly error message.
    </Check>
  </Accordion>
</AccordionGroup>
