# Razorpay SDK Instance Configuration

This module initializes and exports a pre-configured Razorpay SDK instance, centralizing API key management and ensuring consistent payment gateway interaction across the application. It serves as a single source of truth for Razorpay configurations.

## Overview

The `razorpay.js` utility file is responsible for creating a singleton instance of the Razorpay SDK. It securely retrieves API keys from environment variables, promoting secure and flexible configuration for all payment processing functionalities. This instance is primarily used by payment-related routes and services, such as `src/routes/payment.js` for handling API requests and potentially `src/models/payment.js` for interacting with the Razorpay API.

## Setup

<Steps>
  <Step title="Configure Razorpay API Keys">
    To integrate with the Razorpay payment gateway, you must provide your API Key ID and Key Secret. Obtain these credentials from your Razorpay Dashboard (typically under Settings > API Keys).
    <Warning>
      Razorpay API keys are highly sensitive credentials. Never hardcode them directly into your source code. Always store them securely as environment variables to prevent accidental exposure and facilitate environment-specific configurations.
    </Warning>
    Add the following variables to your project's `.env` file:
    ```ini
    RAZORPAY_KEY_ID=rzp_test_YOUR_KEY_ID_HERE
    RAZORPAY_KEY_SECRET=YOUR_KEY_SECRET_HERE
    ```
    <Tip>
      For local development, create a `.env` file in your project root. For deployment, configure these variables directly in your hosting environment (e.g., Vercel, AWS, Heroku).
    </Tip>
  </Step>
  <Step title="Install Razorpay SDK (if not already installed)">
    Ensure the official Razorpay Node.js SDK is installed as a project dependency:
    ```bash
    npm install razorpay
    # or
    yarn add razorpay
    ```
  </Step>
  <Step title="Ensure dotenv is configured">
    If you're using `.env` files, make sure your application's entry point (e.g., `src/app.js` or `index.js`) is loading them:
    ```javascript
    // In src/app.js or your main server file
    require('dotenv').config();
    const Razorpay = require("razorpay");
    // ... rest of your application ...
    ```
  </Step>
</Steps>

## Configuration Properties

This module configures the `Razorpay` SDK instance with the following essential properties, which are securely retrieved from environment variables during application startup:

<ParamField name="key_id" type="string" required>
  Your <Tooltip tip="The public identifier for your Razorpay API key. Used to identify your account for API requests.">Razorpay Key ID</Tooltip>. This value is obtained from the `RAZORPAY_KEY_ID` environment variable. It should typically start with `rzp_test_` for test keys or `rzp_live_` for live keys.
</ParamField>

<ParamField name="key_secret" type="string" required>
  Your <Tooltip tip="The private, secret credential that authenticates your requests to the Razorpay API. Must be kept confidential.">Razorpay Key Secret</Tooltip>. This value is obtained from the `RAZORPAY_KEY_SECRET` environment variable.
</ParamField>

<Warning>
  Failure to properly set the `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` environment variables will prevent the application from successfully initializing the Razorpay SDK, leading to authentication errors and payment processing failures.
</Warning>

## Exported Instance

This module directly exports a pre-configured instance of the `Razorpay` SDK. This `instance` provides access to all Razorpay API methods (e.g., `orders`, `payments`, `refunds`, `webhooks`) through its internal properties.

### `razorpayInstance`

A configured instance of the Razorpay SDK, ready for API calls.

#### Example Instance Method Documentation

While the module itself exports the instance, here's how you might conceptualize the documentation for its commonly used methods:

<ParamField name="orders.create(options)" type="function">
  Initiates the creation of a new payment order with Razorpay.
  <Expandable title="options properties">
    <ParamField name="amount" type="number" required>
      The order amount, specified in the smallest currency unit (e.g., for Indian Rupees, this would be in paisa). Example: `50000` for ₹500.00.
    </ParamField>
    <ParamField name="currency" type="string" default="INR">
      The currency code for the payment, following ISO 4217 standards. Defaults to `INR` (Indian Rupees).
    </ParamField>
    <ParamField name="receipt" type="string">
      A unique identifier for the order from your internal system. This is an optional field.
    </ParamField>
    <ParamField name="payment_capture" type="number" default="1">
      Determines whether to automatically capture the payment after successful authorization. Set to `1` for auto-capture, `0` for manual capture.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="order" type="object">
  The created order object returned by Razorpay, containing details such as `id`, `amount`, `currency`, and `status`. This object is essential for proceeding with the payment process on the client-side.
</ResponseField>

## Usage Example

To leverage the configured Razorpay instance in other modules, simply import it and invoke the necessary API methods. A typical use case involves creating a new payment order for a transaction. This example demonstrates how `src/routes/payment.js` might utilize this instance.

<CodeGroup>
```javascript src/routes/payment.js
const razorpay = require('../utils/razorpay'); // Import the pre-configured instance

/**
 * @route POST /api/payment/order
 * @desc Creates a new Razorpay order for a payment transaction.
 * @access Private (requires authentication middleware)
 */
exports.createOrder = async (req, res) => {
  // Assume amount is sent in smallest currency unit (e.g., paisa)
  const { amount, currency, receipt } = req.body; 

  try {
    const options = {
      amount: amount, 
      currency: currency || "INR",
      receipt: receipt || `receipt_order_${Date.now()}`,
      payment_capture: 1 // Automatically capture payment upon successful authorization
    };

    const order = await razorpay.orders.create(options);
    <Check>
      Successfully created Razorpay order. The `order` object can now be sent to the client for payment initiation.
    </Check>
    res.status(200).json({ success: true, order });

  } catch (error) {
    console.error("Error creating Razorpay order:", error);
    <Danger>
      Failed to create order due to an API error. Check server logs for details.
    </Danger>
    res.status(500).json({ 
      success: false, 
      message: "Failed to create order", 
      error: error.message 
    });
  }
};
```

## Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="`key_id` or `key_secret` is undefined during initialization">
    This error indicates that the `RAZORPAY_KEY_ID` or `RAZORPAY_KEY_SECRET` environment variables could not be accessed when the `razorpay.js` module was loaded.
    <Steps>
      <Step title="Verify `.env` file configuration">
        Ensure you have a `.env` file in your project root and that both `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` are correctly defined within it.
        ```ini
        RAZORPAY_KEY_ID=rzp_test_YOUR_KEY_ID
        RAZORPAY_KEY_SECRET=YOUR_KEY_SECRET
        ```
      </Step>
      <Step title="Check `dotenv` initialization">
        Confirm that your application's entry point (e.g., `src/app.js`) is calling `require('dotenv').config()` early in the startup process, before `src/utils/razorpay.js` is imported.
      </Step>
      <Step title="Restart the server">
        Environment variables are typically loaded only once when the application starts. Always restart your development server after making changes to your `.env` file to ensure they are reloaded.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Razorpay API returns 'Invalid API Key provided' or authentication errors">
    If Razorpay responds with an authentication failure, it means the provided `key_id` or `key_secret` is incorrect, inactive, or revoked.
    <Steps>
      <Step title="Double-check API keys in Razorpay Dashboard">
        Log in to your Razorpay Dashboard and navigate to `Settings > API Keys`. Carefully verify that the Key ID and Key Secret you're using match the active keys in your account. Copy them directly to avoid typos.
      </Step>
      <Step title="Ensure correct environment keys are used">
        If you have separate test and live Razorpay accounts, confirm that you are using the appropriate keys for your current environment (e.g., `rzp_test_...` for development/staging, `rzp_live_...` for production).
      </Step>
      <Step title="Generate new API keys (if necessary)">
        If you suspect your existing keys are compromised or have been deactivated, you can generate new API keys from the Razorpay Dashboard and update your environment variables accordingly.
      </Step>
    </Steps>
  </Accordion>
</AccordionGroup>
