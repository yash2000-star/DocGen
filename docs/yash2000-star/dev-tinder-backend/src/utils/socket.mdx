# Real-time Communication with Socket.IO

This file, `src/utils/socket.js`, is responsible for setting up and managing the Socket.IO server, enabling real-time communication features such as instant messaging within the application. It handles client connections, manages chat rooms, and facilitates the sending and receiving of messages, integrating directly with the `Chat` model for message persistence.

## Overview

The `socket.js` utility initializes the Socket.IO server, binding it to the main HTTP server. It defines event listeners for client connections, disconnections, joining specific chat rooms, and sending messages. Messages are stored in the database and broadcast to relevant participants in real-time. This module is essential for delivering a dynamic and interactive user experience.

## Setup / Installation

To integrate the Socket.IO real-time functionality into your application, follow these steps.

<Steps>
  <Step title="Install Socket.IO">
    If you haven't already, install the `socket.io` library as a dependency in your project.
    ```bash
    npm install socket.io
    ```
  </Step>
  <Step title="Import and Initialize">
    Import the `initializeSocket` function into your main application file (e.g., `src/app.js`) and pass your HTTP server instance to it. This should happen after your HTTP server is created and ready to listen.
    ```javascript
    // src/app.js (example)
    const http = require('http');
    const app = require('./app'); // Your Express app
    const initializeSocket = require('./utils/socket'); // The socket utility

    const server = http.createServer(app);
    const io = initializeSocket(server); // Initialize Socket.IO with your HTTP server

    server.listen(process.env.PORT || 3000, () => {
      console.log(`Server listening on port ${process.env.PORT || 3000}`);
      console.log('Socket.IO initialized.');
    });
    ```
  </Step>
  <Step title="Configure CORS Origins">
    Review and update the `cors.origin` setting within the `initializeSocket` function to securely allow connections from your frontend application's domain.
    <Note>
      The current configuration dynamically sets the origin based on `process.env.NODE_ENV`. For production, ensure `https://www.your-live-app-domain.com` is replaced with your actual live frontend URL.
    </Note>
  </Step>
</Steps>

## Parameters / Configuration

#### `initializeSocket(server)`

This function initializes the Socket.IO server and binds it to an existing HTTP server instance.

<ParamField name="server" type="http.Server" required>
  The HTTP server instance to which Socket.IO will attach. This is commonly created using `http.createServer()` or implicitly from an Express application instance.
</ParamField>

<Info>
  The Socket.IO server's Cross-Origin Resource Sharing (CORS) policy is configured dynamically. In a production environment, it is critical to replace the placeholder `https://www.your-live-app-domain.com` with your actual live frontend domain to prevent security vulnerabilities.
</Info>

## Functions / Routes / Classes

#### `initializeSocket(server)`

Initializes the Socket.IO server and sets up all necessary event listeners for handling real-time communication. It returns the configured Socket.IO server instance.

<ParamField name="server" type="http.Server" required>
  The Node.js HTTP server instance to integrate Socket.IO with.
</ParamField>

<ResponseField name="io" type="Socket.IO.Server">
  The initialized Socket.IO server object, which can be used to emit events globally or manage other aspects of the real-time server.
</ResponseField>

#### Socket.IO Event Handlers

The `initializeSocket` function configures various event handlers that respond to client-side Socket.IO events.

##### `connection` Event

This event is triggered server-side whenever a new client successfully establishes a WebSocket connection with the Socket.IO server.

<Info>
  The server logs the unique `socket.id` for each new connection, which can be useful for debugging and tracking active users.
</Info>

##### `joinChat` Event

Clients emit this event to join a specific chat room. The chat room name is derived from a cryptographic hash of the sorted participant IDs, ensuring a consistent room identifier for any pair of users.

<ParamField name="userId" type="string" required>
  The unique identifier of the user initiating the `joinChat` request.
</ParamField>
<ParamField name="targetUserId" type="string" required>
  The unique identifier of the other participant in the chat.
</ParamField>

<Tip>
  The `roomName` is generated by creating a SHA256 hash of the sorted concatenation of `userId` and `targetUserId`. This guarantees that both participants will attempt to join and broadcast to the same chat room regardless of which user initiates the chat.
</Tip>

<CodeGroup>
```javascript Client-side Example
// Client-side code to join a chat room
socket.emit('joinChat', { userId: 'user_123', targetUserId: 'user_456' });
```
</CodeGroup>

##### `sendMessage` Event

Clients emit this event to send a message to another user within a chat. The message is first saved to the database via the `Chat` model and then broadcast to the relevant chat room.

<ParamField name="senderId" type="string" required>
  The ID of the user sending the message.
</ParamField>
<ParamField name="targetUserId" type="string" required>
  The ID of the intended recipient of the message.
</ParamField>
<ParamField name="text" type="string" required>
  The content of the message to be sent.
</ParamField>

<Warning>
  If any of `senderId`, `targetUserId`, or `text` are missing from the `sendMessage` payload, the message will not be processed, saved, or broadcast, and an error will be logged server-side. Ensure robust client-side validation for these fields.
</Warning>

<Check>
  Messages are persisted to the `Chat` model in the database before being broadcast. If a chat record between the specified participants does not yet exist, a new one is automatically created.
</Check>

<CodeGroup>
```javascript Client-side Example
// Client-side code to send a message
socket.emit('sendMessage', {
  senderId: 'user_123',
  targetUserId: 'user_456',
  text: 'Hey, are you free this weekend?'
});
```
```javascript Server-side Broadcast
// Server-side (implicit within sendMessage handler)
socket.broadcast.to(roomName).emit('messageReceived', { senderId, text });
```
</CodeGroup>

##### `disconnect` Event

This event is fired when a client's Socket.IO connection is terminated, either intentionally by the client or due to network issues.

<Info>
  The server logs the `socket.id` of the client that has disconnected. This can be used for session management or tracking online status.
</Info>

## Usage Example

Below is a typical example of how the `initializeSocket` utility would be integrated into a Node.js Express application's main entry file, such as `src/app.js`.

<CodeGroup>
```javascript src/app.js
const express = require('express');
const http = require('http');
const initializeSocket = require('./utils/socket'); // Your Socket.IO utility
const connectDB = require('./config/database');     // Assuming a database connection utility

// Initialize Express application
const app = express();

// Connect to MongoDB (example)
// Ensure your database connection is established before starting the server
connectDB();

// Create an HTTP server from the Express app
const server = http.createServer(app);

// Initialize the Socket.IO server
// This attaches Socket.IO to your existing HTTP server
const io = initializeSocket(server);

// Example Express route
app.get('/', (req, res) => {
  res.send('API is running and Socket.IO is active.');
});

// Start the HTTP server, which also hosts the Socket.IO server
const PORT = process.env.PORT || 3000;
server.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```
</CodeGroup>

## Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="CORS policy is blocking Socket.IO connections">
    <Info>
      This is a common issue where the client-side application's origin does not match the allowed origins configured on the Socket.IO server.
    </Info>
    <Tip>
      Ensure that the `cors.origin` setting in `src/utils/socket.js` exactly matches your client-side application's URL, including the protocol (http/https) and port.
    </Tip>
    <CodeGroup>
    ```javascript Corrected CORS example
    const io = new Server(server, {
      cors: {
        // This must match your frontend's full URL
        origin: process.env.NODE_ENV === "production"
          ? "https://your-live-app-domain.com"
          : "http://localhost:5173", // Example: if your frontend runs on this address
        credentials: true,
      },
    });
    ```
    ```bash Browser Console Error
    Access to XMLHttpRequest at 'http://localhost:3000/socket.io/?EIO=4&transport=polling&t=N9gQ30H' from origin 'http://localhost:5173' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
    ```
    </CodeGroup>
  </Accordion>
  <Accordion title="Messages are not being saved to the database or broadcast">
    <Info>
      This can happen due to missing data in the `sendMessage` event or problems with the database connection or `Chat` model.
    </Info>
    <Steps>
      <Step title="Verify client payload for `sendMessage`">
        Confirm that your client is sending all required fields (`senderId`, `targetUserId`, `text`) to the `sendMessage` event.
        ```javascript
        socket.emit('sendMessage', { senderId: '...', targetUserId: '...', text: '...' });
        ```
      </Step>
      <Step title="Check server logs">
        Look for error messages in your server console such as `sendMessage event received with missing data.` or `Error in sendMessage:`.
      </Step>
      <Step title="Inspect database connection and `Chat` model">
        Ensure your MongoDB connection (e.g., via `src/config/database.js`) is active and that the `src/models/chat.js` model is correctly defined and accessible.
      </Step>
    </Steps>
  </Accordion>
  <Accordion title="Client is not receiving broadcasted messages">
    <Info>
      If messages are saved to the database but not appearing on the client-side, the client might not be in the correct chat room or is not listening for the `messageReceived` event.
    </Info>
    <Steps>
      <Step title="Confirm client `joinChat` operation">
        Ensure the client successfully emits the `joinChat` event with correct `userId` and `targetUserId` values immediately after connecting. Server logs should confirm the user joining the room.
      </Step>
      <Step title="Verify `messageReceived` listener">
        Check that the client-side code has an active listener for the `messageReceived` event.
        ```javascript Client-side Example
        socket.on('messageReceived', (data) => {
          console.log('New message received:', data);
          // Logic to display the message in UI
        });
        ```
      </Step>
      <Step title="Cross-check room name generation">
        Ensure that the logic for generating the `roomName` is identical and consistent between the server-side `joinChat` and `sendMessage` handlers to ensure clients are in the expected room.
      </Step>
    </Steps>
  </Accordion>
</AccordionGroup>
