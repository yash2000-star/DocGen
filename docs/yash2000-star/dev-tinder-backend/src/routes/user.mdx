# User Routes

This file defines the API routes related to user profiles, connection requests, and the user feed. It leverages Express.js for routing and interacts with `ConnectionRequestModel` and `User` models to manage and retrieve user-centric data, ensuring all operations are authenticated via the `userAuth` middleware.

## Overview

The `userRouter` module aggregates several endpoints that enable authenticated users to fetch their profile details, manage connection requests, and discover new users through a personalized feed. It relies on a consistent data structure for user information and robust error handling.

<CardGroup cols={2}>
  <Card title="User Profiles" icon="👤">
    Provides an endpoint to retrieve a user's public profile by ID.
  </Card>
  <Card title="Connection Management" icon="🤝">
    Handles fetching received connection requests and established user connections.
  </Card>
  <Card title="User Feed Generation" icon="📰">
    Delivers a paginated list of potential new connections, excluding already connected or requested users.
  </Card>
  <Card title="Authentication" icon="🔐">
    All routes in this module are protected by the `userAuth` middleware, ensuring only authenticated users can access them.
  </Card>
</CardGroup>

<Info>
  This module imports and utilizes the `userAuth` middleware from `src/middleware/auth.js` to enforce authentication for all its routes. It also depends on the `ConnectionRequestModel` (from `src/models/connectionRequest.js`) and `User` model (from `src/models/user.js`) for database interactions.
</Info>

## API Routes

### Get User by ID

Retrieves a user's profile details by their unique ID, excluding sensitive information like the password.

**Endpoint:** `GET /get-user-by-id/:userId`

<Note>
  This endpoint uses `USER_SAFE_DATA` to populate only `firstName`, `lastName`, `photoUrl`, `age`, `gender`, `about`, and `skills` fields when querying user data from the database.
</Note>

#### Parameters

<ParamField name="userId" type="string" required>
  The unique identifier of the user to retrieve. This is a path parameter.
</ParamField>

#### Responses

<ResponseField name="data" type="object">
  The user object, containing non-sensitive profile information. Returns `null` if the user is not found.
  <Expandable title="data properties">
    <ResponseField name="data.id" type="string">The user's unique ID.</ResponseField>
    <ResponseField name="data.firstName" type="string">The user's first name.</ResponseField>
    <ResponseField name="data.lastName" type="string">The user's last name.</ResponseField>
    <ResponseField name="data.photoUrl" type="string">URL to the user's profile photo.</ResponseField>
    <ResponseField name="data.age" type="number">The user's age.</ResponseField>
    <ResponseField name="data.gender" type="string">The user's gender.</ResponseField>
    <ResponseField name="data.about" type="string">A brief description about the user.</ResponseField>
    <ResponseField name="data.skills" type="array<string>">A list of skills the user possesses.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="message" type="string">
  A descriptive message for error responses, e.g., "User not found" or "Server Error".
</ResponseField>

#### Usage Example

<RequestExample>
```bash cURL
curl -X GET https://api.example.com/get-user-by-id/654321098765432109876543 \
  -H "Authorization: Bearer YOUR_AUTH_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200 OK
{
  "data": {
    "_id": "654321098765432109876543",
    "firstName": "Jane",
    "lastName": "Doe",
    "photoUrl": "https://example.com/jane.jpg",
    "age": 28,
    "gender": "female",
    "about": "Passionate about tech.",
    "skills": ["JavaScript", "React"]
  }
}
```

```json 404 Not Found
{
  "message": "User not found"
}
```
</ResponseExample>

### Get Received Connection Requests

Retrieves all pending connection requests where the logged-in user is the recipient and the request status is "interested".

**Endpoint:** `GET /user/requests/received`

#### Responses

<ResponseField name="message" type="string">
  A confirmation message, e.g., "Data fetched successfully".
</ResponseField>
<ResponseField name="data" type="array<object>">
  An array of connection request objects. Each object includes details of the sender (`fromUserId`) populated with safe user data.
  <Expandable title="data item properties">
    <ResponseField name="data[]._id" type="string">The ID of the connection request.</ResponseField>
    <ResponseField name="data[].fromUserId" type="object">The user who sent the request, populated with `USER_SAFE_DATA`.</ResponseField>
    <ResponseField name="data[].toUserId" type="string">The ID of the user who received the request (the logged-in user).</ResponseField>
    <ResponseField name="data[].status" type="string">The status of the request (e.g., "interested").</ResponseField>
    <ResponseField name="data[].createdAt" type="string">Timestamp when the request was created.</ResponseField>
    <ResponseField name="data[].updatedAt" type="string">Timestamp when the request was last updated.</ResponseField>
  </Expandable>
</ResponseField>

#### Usage Example

<RequestExample>
```bash cURL
curl -X GET https://api.example.com/user/requests/received \
  -H "Authorization: Bearer YOUR_AUTH_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200 OK
{
  "message": "Data fetched successfully",
  "data": [
    {
      "_id": "654321098765432109876544",
      "fromUserId": {

        "photoUrl": "https://example.com/alice.jpg",
        "age": 30,
        "gender": "female",
        "about": "Looking for connections.",
        "skills": ["Node.js", "MongoDB"]
      },
      "toUserId": "654321098765432109876543",
      "status": "interested",
      "createdAt": "2023-10-27T10:00:00.000Z",
      "updatedAt": "2023-10-27T10:00:00.000Z"
    }
  ]
}
```
</ResponseExample>

### Get User Connections

**Endpoint:** `GET /user/connections`

#### Responses

<ResponseField name="data" type="array<object>">
  An array of connection request objects where the status is "accepted". Both `fromUserId` and `toUserId` are populated with safe user data.
  <Expandable title="data item properties">
    <ResponseField name="data[]._id" type="string">The ID of the connection request.</ResponseField>
    <ResponseField name="data[].fromUserId" type="object">The user who initiated the request, populated with `USER_SAFE_DATA`.</ResponseField>
    <ResponseField name="data[].toUserId" type="object">The user who received the request, populated with `USER_SAFE_DATA`.</ResponseField>
    <ResponseField name="data[].status" type="string">The status of the request ("accepted").</ResponseField>

### Get User Feed

Generates a paginated list of potential users for the logged-in user's feed. This endpoint intelligently filters out users with whom the logged-in user already has an active connection (either initiated or received) or users who are themselves the logged-in user.

**Endpoint:** `GET /feed`

#### Parameters

<ParamField name="page" type="number" default="1">
  The page number for pagination. This is a query parameter.
</ParamField>
<ParamField name="limit" type="number" default="10">
  The maximum number of users to return per page. Maximum allowed limit is 50. This is a query parameter.
</ParamField>

#### Responses

<ResponseField name="data" type="array<object>">
  An array of user objects that are potential connections. Each user object contains safe profile data.
  <Expandable title="data item properties">
    <ResponseField name="data[]._id" type="string">The user's unique ID.</ResponseField>
    <ResponseField name="data[].firstName" type="string">The user's first name.</ResponseField>
    <ResponseField name="data[].lastName" type="string">The user's last name.</ResponseField>
    <ResponseField name="data[].photoUrl" type="string">URL to the user's profile photo.</ResponseField>
    <ResponseField name="data[].age" type="number">The user's age.</ResponseField>
    <ResponseField name="data[].gender" type="string">The user's gender.</ResponseField>
    <ResponseField name="data[].about" type="string">A brief description about the user.</ResponseField>
    <ResponseField name="data[].skills" type="array<string>">A list of skills the user possesses.</ResponseField>
  </Expandable>
</ResponseField>

#### Usage Example

<RequestExample>
```bash cURL
curl -X GET "https://api.example.com/feed?page=1&limit=5" \
```

## Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication Failure (401 Unauthorized)">
    <Info>
      All routes in `user.js` require a valid JWT token in the `Authorization` header. If you receive a 401 error, ensure your token is present, unexpired, and correctly formatted (`Bearer YOUR_AUTH_TOKEN`).
    </Info>
    Check the `userAuth` middleware (in `src/middleware/auth.js`) for details on token validation.
  </Accordion>
  <Accordion title="User Not Found (404 Not Found) for `/get-user-by-id/:userId`">
    This error indicates that the `userId` provided in the path parameter does not correspond to an existing user in the database.
    <Tip>
      Double-check the `userId` for typos or incorrect values. Ensure the user exists and has not been deleted.
    </Tip>
  </Accordion>
  <Accordion title="Server Error (500 Internal Server Error)">
    This is a generic error indicating an unexpected issue on the server side. It could be due to database connection problems, unhandled exceptions in the route logic, or issues with model interactions.
    <Note>
      Check the backend logs for more specific error messages, which will typically provide a stack trace or a more detailed reason for the failure.
    </Note>
  </Accordion>
  <Accordion title="Bad Request (400) for `/feed`">
    This usually implies an issue with query parameters like `page` or `limit`. While the code parses them, invalid non-numeric inputs might lead to issues.
    <Tip>
      Ensure `page` and `limit` are positive integers. The `limit` will be capped at 50 if a higher value is provided.
    </Tip>
  </Accordion>
</AccordionGroup>
