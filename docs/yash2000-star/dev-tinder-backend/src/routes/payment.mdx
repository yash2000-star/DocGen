# Payment Routes

This file defines the API routes for handling payment operations within the application, including initiating new payment orders, processing Razorpay webhooks for payment status updates, and verifying user premium status.

## Overview

This module is responsible for integrating with the Razorpay payment gateway to manage user memberships. It provides endpoints to create payment orders, listen for payment completion or failure events via webhooks, and expose the user's premium status.

<CardGroup cols={2}>
  <Card title="Payment Initiation" icon="💰">

  </Card>
  <Card title="Webhook Handling" icon="🔗">

## `POST /payment/create`

Initiates a new payment order with Razorpay for a specified membership type. This route requires user authentication to identify the user making the payment.

<Note>
  This route utilizes the `razorpayInstance` from [`src/utils/razorpay.js`](/src/utils/razorpay.js) and retrieves membership amounts from [`src/utils/constants.js`](/src/utils/constants.js). Payment records are stored using the `Payment` model defined in [`src/models/payment.js`](/src/models/payment.js).
</Note>

### Parameters

<ParamField name="membershipType" type="string" required>
  The type of membership the user wishes to purchase. This must correspond to a predefined membership type in the application's constants (e.g., "premium", "gold").
</ParamField>

### Response

<ResponseField name="id" type="string">
  The unique ID of the created payment record.
</ResponseField>
<ResponseField name="userId" type="string">
  The ID of the user who initiated the payment.
</ResponseField>
<ResponseField name="orderId" type="string">
  The order ID generated by Razorpay.
</ResponseField>
<ResponseField name="status" type="string">
  The current status of the payment order (e.g., "created").
</ResponseField>
<ResponseField name="amount" type="number">
  The amount of the payment in the smallest currency unit (e.g., paise for INR).
</ResponseField>
<ResponseField name="currency" type="string">
  The currency code for the payment (e.g., "INR").
</ResponseField>
<ResponseField name="receipt" type="string">
  A unique receipt identifier for the payment.
</ResponseField>
<ResponseField name="notes" type="object">
  <Expandable title="notes properties">
    <ResponseField name="firstName" type="string">User's first name.</ResponseField>
    <ResponseField name="lastName" type="string">User's last name.</ResponseField>
    <ResponseField name="emailId" type="string">User's email ID.</ResponseField>
    <ResponseField name="membershipType" type="string">The requested membership type.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="keyId" type="string">
  Your Razorpay Key ID, required for client-side integration to complete the payment.
</ResponseField>

<Warning>
  The `keyId` returned in the response is your public Razorpay API key. Ensure that this key is stored securely in your environment variables (`process.env.RAZORPAY_KEY_ID`) and never hardcoded in client-side code.
</Warning>

### `POST /payment/webhook`

Handles incoming webhook notifications from Razorpay to update the payment status and assign premium membership to the user. This route is public as it's called directly by Razorpay.

<Info>
  This route uses the `Payment` model and `User` model (from [`src/models/payment.js`](/src/models/payment.js) and [`src/models/user.js`](/src/models/user.js) respectively) to update database records based on webhook events. It also utilizes `razorpay/dist/utils/razorpay-utils` for signature validation.
</Info>

### Parameters

<ParamField name="X-Razorpay-Signature" type="string" required format="header">
  The signature sent by Razorpay in the request header, used to verify the authenticity of the webhook.
</ParamField>
<ParamField name="req.body" type="object" required>
  The full payload sent by Razorpay containing details about the payment event.
</ParamField>

<Warning>
  Webhook signature validation is crucial for security. It ensures that the incoming request genuinely originated from Razorpay and prevents spoofing. The `process.env.RAZORPAY_WEBHOOK_SECRET` must be kept confidential and never exposed.
</Warning>

### Response

<ResponseField name="msg" type="string">
  A success message "Webhook received successfully" on successful processing, or an error message otherwise.
</ResponseField>

### `GET /premium/verify`

Verifies the premium status of the authenticated user. This route requires user authentication.

<Info>
  This route relies on the `userAuth` middleware (from [`src/middleware/auth.js`](/src/middleware/auth.js)) to populate `req.user` with the authenticated user's details, which are then used to check `isPremium` status.
</Info>

### Parameters

This route does not accept any explicit parameters beyond the authentication token provided in the request headers.

### Response

<ResponseField name="user" type="object">
  The authenticated user object, including their `isPremium` status and `membershipType`.
  <Expandable title="user properties">

    <ResponseField name="lastName" type="string">The user's last name.</ResponseField>
    <ResponseField name="isPremium" type="boolean">Indicates if the user has a premium membership.</ResponseField>
    <ResponseField name="membershipType" type="string | null">The type of premium membership the user holds, or `null` if not premium.</ResponseField>
    {/* ... other user properties can be added if relevant */}
  </Expandable>
</ResponseField>

## Usage Example

Here's how you might interact with the `/payment/create` endpoint to initiate a payment.

<CodeGroup>
```bash cURL
curl -X POST https://api.example.com/payment/create \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_AUTH_TOKEN" \
  -d '{"membershipType": "premium"}'
```
```javascript JavaScript
async function createPaymentOrder(membershipType) {
  const response = await fetch('https://api.example.com/payment/create', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer YOUR_AUTH_TOKEN',
    },
    body: JSON.stringify({ membershipType }),
  });
  const data = await response.json();
  if (response.ok) {
    console.log('Payment order created:', data);
    // You would then use data.keyId and data.orderId to open the Razorpay checkout
  } else {
    console.error('Failed to create payment order:', data);
  }
}

createPaymentOrder('premium');
```
</CodeGroup>

## Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="Invalid membership type during payment creation">
    If the `membershipType` provided to `/payment/create` does not match any configured types in `src/utils/constants.js`, the API will return a `400 Bad Request`. Ensure your client-side code sends a valid `membershipType`.
    ```json
    {
      "error": "Invalid membership type"
    }
    ```
  </Accordion>
  <Accordion title="Webhook signature mismatch">
    If Razorpay's webhook signature (`X-Razorpay-Signature`) does not match the computed signature using your `RAZORPAY_WEBHOOK_SECRET`, the `/payment/webhook` endpoint will return a `400 Bad Request`. This usually indicates:
    -   An incorrect `RAZORPAY_WEBHOOK_SECRET` environment variable.
    -   The webhook payload was tampered with.
    -   A mismatch in how the payload is `JSON.stringify`'d between Razorpay and your server.
    Ensure your `RAZORPAY_WEBHOOK_SECRET` is correctly set and matches the one configured in your Razorpay dashboard for the webhook.
    ```json
    {
      "msg": "Invalid webhook signature"
    }
    ```
  </Accordion>
  <Accordion title="Internal Server Error (500)">
    A `500 Internal Server Error` from any of these routes indicates an unhandled exception on the server. Common causes include:
    -   Database connection issues or errors during Mongoose operations.
    -   Incorrect Razorpay API key/secret configuration preventing order creation.
    -   Malformation of `req.body` or `req.user` if middleware is not functioning correctly.
    Check server logs for specific error messages to diagnose the root cause.
  </Accordion>
</AccordionGroup>
