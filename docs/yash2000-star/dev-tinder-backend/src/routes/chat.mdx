# Chat API Endpoints

This module defines API routes for managing and retrieving user chat conversations within the application. It provides functionality to fetch existing chats between two users or initiate a new chat session.

## Overview

The `chat.js` file exposes endpoints related to direct messaging functionality. It primarily handles the logic for retrieving a chat session based on participant IDs, creating a new session if one doesn't exist, and populating message sender details for display. This route integrates with the `userAuth` middleware to ensure secure, authenticated access, operating on the `Chat` model.

## `GET /chat/:targetUserId`

Retrieves an existing chat session between the authenticated user and a specified `targetUserId`, or creates a new empty chat session if none exists.

<Info>
  This endpoint requires the user to be authenticated via the `userAuth` middleware (from `src/middleware/auth.js`), which verifies a JWT token and attaches the authenticated user's details (`req.user`) to the request object. The authenticated user's ID (`req.user._id`) is used as one of the chat participants.
</Info>

### Parameters

<ParamField name="targetUserId" type="string" required>
  The unique identifier of the other user participating in the chat. This ID is expected as a URL path parameter.
</ParamField>

### Response

Returns the chat object, either an existing conversation or a newly created one. The `messages.senderId` field is populated with `firstName` and `lastName` of the sender.

<ResponseField name="_id" type="string">
  The unique identifier of the chat session.
</ResponseField>
<ResponseField name="participants" type="array<string>" required>
  An array containing the unique IDs of the two users participating in the chat.
</ResponseField>
<ResponseField name="messages" type="array<object>">
  An array of message objects within the chat. This array can be empty if it's a newly created chat.
  <Expandable title="message properties">
    <ResponseField name="messages.senderId" type="object">
      The user object of the message sender, populated with their `firstName` and `lastName`.
      <Expandable title="senderId properties">
        <ResponseField name="messages.senderId._id" type="string">
          The unique ID of the message sender.
        </ResponseField>
        <ResponseField name="messages.senderId.firstName" type="string">
          The first name of the message sender.
        </ResponseField>
        <ResponseField name="messages.senderId.lastName" type="string">
          The last name of the message sender.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="messages.content" type="string">
      The textual content of the message.
    </ResponseField>
    <ResponseField name="messages.timestamp" type="string">
      The ISO 8601 timestamp when the message was sent.
    </ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="createdAt" type="string">
  The ISO 8601 timestamp when the chat session was created.
</ResponseField>
<ResponseField name="updatedAt" type="string">
  The ISO 8601 timestamp when the chat session was last updated.
</ResponseField>

### Relationships

This `chatRouter` directly interacts with the following modules:
-   **`src/middleware/auth.js`**: Specifically, the `userAuth` middleware is imported and applied to this route, ensuring that only authenticated users can access the chat functionality.
-   **`src/models/chat.js`**: It imports the `Chat` Mongoose model to perform database operations, including finding an existing chat document or creating a new one if it doesn't exist. The chat schema defines the structure for `participants` and `messages`.
