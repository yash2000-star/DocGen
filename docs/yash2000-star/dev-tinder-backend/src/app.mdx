# Application Entry Point and Server Setup

This file (`src/app.js`) serves as the primary entry point for the DevTinder backend application. It initializes the Express.js server, configures essential middleware, mounts all application routes, establishes the database connection, and sets up the WebSocket server using Socket.io.

## Overview

The `app.js` file orchestrates the entire backend application, bringing together various components like routing, database interactions, and real-time communication. It ensures that the server is properly configured and ready to handle incoming API requests and WebSocket connections.

<CardGroup cols={3}>
  <Card title="Server Initialization" icon="🚀">
    Sets up the Express.js application and HTTP server instance.
  </Card>
  <Card title="Middleware & Routing" icon="⚙️">
    Configures critical middleware like CORS, JSON parsing, and mounts all API routes.
  </Card>
  <Card title="Database & Realtime" icon="🔗">
    Manages the database connection and initializes the Socket.io server for real-time features.
  </Card>

## Setup and Configuration

This module relies on environment variables for sensitive configurations and global settings. Ensure your `.env` file is properly set up.

<Steps>
  <Step title="Environment Variables">
    The application uses `dotenv` to load environment variables. Create a `.env` file in your project root with necessary configurations such as database connection strings, JWT secrets, and any third-party API keys.
    <Warning>
      Never commit your `.env` file to version control. Use a `.env.example` file with placeholder values instead.
    </Warning>
  </Step>
  <Step title="Database Configuration">
    Ensure your database is accessible and its connection details are correctly specified in your environment variables, which are then utilized by the `src/config/database.js` module.
    <Note>
      The application automatically attempts to connect to the database upon startup.
    </Note>
  </Step>
</Steps>

### Configuration Parameters

The `app.js` file configures several core aspects of the server, including Cross-Origin Resource Sharing (CORS) policies.

<ParamField name="allowedOrigins" type="string[]">
  An array of allowed client origins that are permitted to access the API. Requests from any other origin will be blocked by the CORS policy.
  <Expandable title="Example origins">
    <ParamField name="allowedOrigins[0]" type="string" default="http://localhost:5173">
      Local development client URL.
    </ParamField>
    <ParamField name="allowedOrigins[1]" type="string" default="https://devtinder.yashwant.xyz">
      Production client URL.
    </ParamField>
  </Expandable>
  <Warning>
    Carefully manage `allowedOrigins` in production. Allowing too many origins can expose your API to unauthorized access.
  </Warning>
</ParamField>

## Core Components and Middleware

### Express Application Instance

The core Express application instance, `app`, is created and configured with global middleware.

<CodeGroup>
```javascript app.js
const express = require('express');
const app = express();
```
</CodeGroup>

### CORS Middleware

This middleware handles Cross-Origin Resource Sharing, controlling which origins are permitted to make requests to the API.

<ParamField name="origin" type="function(origin, callback)" required>
  A function that checks the incoming request's `Origin` header against a predefined list of `allowedOrigins`.
</ParamField>
<ParamField name="credentials" type="boolean" default="false">
  Enables or disables the `Access-Control-Allow-Credentials` response header. Set to `true` to allow cookies, authorization headers, or TLS client certificates to be sent with cross-origin requests.
  <Warning>
    Setting `credentials: true` without carefully restricting `origin` can lead to security vulnerabilities like CSRF attacks if not properly mitigated by the client-side.
  </Warning>
</ParamField>

### Body Parsing Middleware

`express.json()` parses incoming requests with JSON payloads, making them available on `req.body`.

<CodeGroup>
```javascript app.js
app.use(express.json());
```
</CodeGroup>

### Cookie Parsing Middleware

`cookie-parser` parses `Cookie` headers and populates `req.cookies` with an object keyed by cookie names.

<CodeGroup>
```javascript app.js
app.use(cookieParser());
```
</CodeGroup>

### Socket.io Initialization

Initializes the WebSocket server for real-time communication functionalities within the application.

<ParamField name="server" type="http.Server" required>
  The HTTP server instance to which Socket.io will attach. This allows Socket.io to share the same port as the Express application.
</ParamField>

<CodeGroup>
```javascript app.js
const server = http.createServer(app);
initializeSocket(server);
```
</CodeGroup>
<Info>
  The `initializeSocket` function is imported from `src/utils/socket.js`. Refer to its documentation for details on WebSocket events and handlers.
</Info>

### Database Connection

Establishes a connection to the MongoDB database using Mongoose. The application will not start listening for requests until a successful database connection is made.

<CodeGroup>
```javascript app.js
connectDB()
.then(() => {
    console.log("Database connection established...");
    server.listen(5000, () => {
    console.log("Server is successfully listening on port 5000...")
});
})
.catch(err => {
    console.log("Databse cannot be connected!!");
    console.error(err);
})
```
</CodeGroup>
<Info>
  The `connectDB` function is imported from `src/config/database.js`. Ensure your MongoDB URI is correctly configured in your `.env` file.
</Info>

## Usage Example

To start the DevTinder backend server, ensure all dependencies are installed and environment variables are set.

<Steps>
  <Step title="Install Dependencies">
    If you haven't already, install all required Node.js packages.
    ```bash
    npm install
    ```
  </Step>
  <Step title="Configure Environment">
    Create a `.env` file in the project root based on a `.env.example` (if provided), filling in your database URI and other necessary secrets.
    ```bash
    cp .env.example .env
    # Edit .env with your specific values
    ```
  </Step>
  <Step title="Start the Server">
    Run the application. The server will listen on port 5000 by default.
    ```bash
    node src/app.js
    ```
    Alternatively, if you have a `start` script defined in your `package.json`:
    ```bash
    npm start
    ```
    Upon successful startup, you will see console messages indicating database connection and server listening.
    <ResponseExample>
    ```text
    Database connection established...
    Server is successfully listening on port 5000...
    ```
    </ResponseExample>
  </Step>
</Steps>

## Common Errors / Troubleshooting

<AccordionGroup>
  <Accordion title="CORS Policy Blocked">
    This error occurs when a client from an origin not listed in `allowedOrigins` attempts to access the API.
    <Steps>
      <Step title="Check `allowedOrigins`">
        Verify that the client's origin URL is correctly listed in the `allowedOrigins` array within `src/app.js`.
      </Step>
      <Step title="Ensure Correct Port/Protocol">
        Make sure the protocol (http/https) and port match exactly. For example, `http://localhost:3000` is different from `http://localhost:5173`.
      </Step>
    </Steps>
    <Tip>
      During development, you might temporarily add `*` to `allowedOrigins` (e.g., `["*"]`) to debug client issues, but **never do this in production environments** as it opens your API to all origins.
    </Tip>
  </Accordion>
  <Accordion title="Database Connection Failed">
    If the server logs "Database cannot be connected!!" and exits, it indicates an issue with the database connection.
    <Steps>
      <Step title="Verify MongoDB URI">
        Ensure the `MONGODB_URI` or equivalent environment variable is correctly set in your `.env` file and points to an accessible MongoDB instance.
      </Step>
      <Step title="Check Database Status">
        Confirm that your MongoDB server is running and accessible from the machine hosting the backend application.
      </Step>
      <Step title="Review Firewall Rules">
        If connecting to a remote database, ensure that network firewalls are not blocking the connection.
      </Step>
    </Steps>
    <Danger>
      A persistent database connection failure will prevent the server from starting, rendering the API unusable. Address these errors immediately.
    </Danger>
  </Accordion>
  <Accordion title="Server Not Listening on Port 5000">
    This could happen if another process is already using port 5000.
    <Steps>
      <Step title="Check Port Availability">
        Use system tools (e.g., `netstat -ano | findstr :5000` on Windows, `lsof -i :5000` on Linux/macOS) to identify if another process is occupying the port.
      </Step>
      <Step title="Terminate Competing Process">
        If another process is using port 5000, terminate it and try restarting the server.
      </Step>
      <Step title="Change Server Port">
        Alternatively, modify the `server.listen` call in `src/app.js` to use a different port (e.g., 8000), or preferably, configure the port via an environment variable (`process.env.PORT`).
      </Step>
    </Steps>
  </Accordion>
</AccordionGroup>
